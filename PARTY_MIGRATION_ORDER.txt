PARTY BACKEND MIGRATION ORDER

The React party screens require the Element 6 party and presence RPCs. If these
migrations have not already been applied to the project's Supabase database, run
them in the Supabase SQL Editor in this order, after the existing Element 6
social/online schema:

1. Supabase-party-table-race-replays.sql
2. Supabase-2026-09-28-party-table-community-replay-fix.sql
3. Supabase-party-presence-completion.sql
4. Supabase-party-reliability-repair.sql
5. Supabase-table-join-concurrency-repair.sql
6. Supabase-table-honored-bot-launch.sql
7. Supabase-party-linked-custom-rooms.sql
8. Supabase-party-table-integration.sql
9. Supabase-custom-room-ready-controls.sql
10. Supabase-Element6-Season-2027-Claims.sql
11. Supabase-online-sports-setup.sql (or the already deployed online sports schema)
12. Supabase-custom-room-sports-renderers.sql
13. Supabase-party-sports-and-host-migration.sql

The Custom Room controls migration adds authoritative ready, presence, settings,
join, start, and snapshot RPCs. It serializes room creation and membership so one
account cannot race into multiple active rooms. It also snapshots account-owned
profile titles onto chat messages and room/party rosters; the title is read from
user progress, not accepted from the message sender. Party launches require each
member to have a recent app-presence heartbeat, avoiding room/Table slots being
created for disconnected party members. The Table roster also snapshots each
participant's equipped title from server-owned account progress. The Custom
Room sports-renderers migration connects the existing shared sport renderer to
server-validated room creation, exact sport rosters, results, recovery
checkpoints, and active-room host epochs. The party sports/host-migration patch
creates one server-linked sports match for a ready party of the exact size
required by the selected sport and elects a new active-match host when the
current host goes stale. These flows use the existing host-authoritative sport
simulation; they do not provide deterministic frame-perfect rollback.

Do not rerun migrations if your deployment process manages them separately.
The party UI cannot create backend tables/functions from frontend code alone.
